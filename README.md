# VelvetDesk AI

Локальный мультиагентный копилот для операторов дейтинг-агентства. Tauri 2 + Rust,
одна кодовая база на **Windows, macOS, Linux и Android**. Данные не покидают устройство.

![build](https://img.shields.io/badge/build-github%20actions-blue) ![license](https://img.shields.io/badge/license-MIT-green)

## Что внутри

| Слой | Реализация |
| --- | --- |
| UI | Vite + TypeScript, Apple-HIG glassmorphism, трёхколоночный воркспейс, мобильный режим с таб-баром |
| Ядро | Rust: изолированное хранилище, движок агентов, доктор, пул ключей |
| Хранилище | JSON-файлы в `AppData/app_data/`, атомарная запись через `.tmp` + rename |
| LLM | Google Gemini (v1/v1beta, native function calling) и любой OpenAI-совместимый endpoint |

### Мультиагентная иерархия

```
Master Agent (глобальный)         — отдельный чат: видит все анкеты, заводит новые вместе с мужчинами
├── Model Agent (в песочнице)     — чат/письма, тон, мутации CRM
├── Doctor Agent                  — валидация схем, починка JSON, целостность индекса
└── Background Memory             — однопроходная синхронизация фактов, подарков, стадий
```

Чат — на каждого мужчину свой, плюс общий чат анкеты, когда никто не выбран.
В общем чате агент получает весь реестр мужчин; в чате мужчины — его досье и переписку.

### Мастер-чат

Вставь список эдмайеров или письмо и скажи, чьё это. Мастер найдёт анкету по имени
или ID, заведёт новую, если её нет, и разложит мужчин по досье — по тем же правилам
безопасности, что и обычный агент. Кнопка `⌗` в топбаре.

### Режимы работы

| Режим | Что делает | Стоимость |
| --- | --- | --- |
| **AUTO** | Модель сама вызывает инструменты: читает досье и историю, пишет ответ, сохраняет факты | несколько вызовов |
| **ACT** | Один вызов → `{reply, memory_patch}`: черновик + патч памяти | 1 вызов |
| **MEMORIZE** | Один вызов → только патч памяти, ответ не генерируется (режим диктовки) | 1 вызов |
| **LETTERS** | Письмо её голосом: одному мужчине или всем из списка сразу | 1 вызов на письмо |

### Письма

Голос модели задаётся образцами её писем в анкете: модель копирует голос по
примерам заметно точнее, чем следует правилам о нём. Письмо собирается из её
персоны и его досье с перепиской, поэтому одно и то же задание у разных анкет
выходит по-разному — короткие сухие строки у одной, длинные с бытовыми деталями
у другой.

Рассылка пишется по одному запросу на человека, а не одним запросом на всех:
общий запрос усредняет письма, а это ровно то, чего в рассылке быть не должно.
Каждое письмо остаётся в том чате, где его заказали.

### Уровни безопасности

| Уровень | Чтение | Добавление/обновление | Удаление, переписывание персоны |
| --- | --- | --- | --- |
| **Ask** | сразу | подтверждение | подтверждение |
| **Safe** (по умолчанию) | сразу | сразу | подтверждение |
| **Full** | сразу | сразу | сразу |

Отдельно от уровней: **папка на диске**. Агент стартует в изоляции и видит только
свои данные. Чтобы прочитать или изменить что-то ещё, он вызывает `request_access`,
и запрос ждёт ответа человека — «Полный доступ» такие разрешения не выдаёт.
Выданная папка запоминается, повторно спрашивать не будет.

| Инструмент | Что делает |
| --- | --- |
| `fs_list` / `fs_read` | смотреть содержимое разрешённой папки |
| `fs_write` / `fs_edit` | записать файл целиком или заменить точный фрагмент |
| `fs_delete` | удалить файл |
| `shell` | одна команда (PowerShell на Windows, bash на остальных), таймаут 120 с |

Перед любой перезаписью и удалением сохраняется копия прежней версии
(`app_data/backups/`), так что доктор может вернуть файл на место.
Запись и команды подчиняются уровню безопасности: ниже «Полного доступа» они ждут
подтверждения.

Каждое отложенное действие показывается как diff «до / после» в очереди (🛡 в топбаре).
Подтверждение перепланирует мутацию заново на актуальных данных — устаревшее в диск не попадёт.

## Изоляция профилей

```
app_data/
  settings.json
  secrets.json                       # API-ключи, chmod 600 на unix
  global_index.json
  profiles/<model_id>/profile.json
  profiles/<model_id>/men/<man_id>.json
  profiles/<model_id>/chats/<man_id>.json
  profiles/<model_id>/agent_log.json
  profiles/<model_id>/attachments/
```

Агент модели получает `Scope`, который:

- принимает только id из `[A-Za-z0-9_-]{1,64}` — точки и слэши отсекаются;
- отклоняет абсолютные пути и любые `..` компоненты;
- канонизирует родительскую директорию и проверяет, что она лежит внутри песочницы (защита от симлинков).

Соседние профили физически недоступны — проверено тестами (`storage::tests::rejects_traversal`).

## Ротация ключей и запасные модели

Лимиты у провайдеров считаются по моделям, а не по ключам, поэтому перебор
двухуровневый: сначала все ключи на текущей модели, затем следующая модель из
цепочки — и снова с первого ключа. При переходе кулдауны сбрасываются: ключ,
упёршийся в квоту одной модели, для следующей свободен. Цепочка настраивается
в 🔑 → «Если модель не отвечает», а в строке ответа видно, какая модель его
написала.

Пул на провайдера, round-robin. Вердикты и кулдауны:

| Код | Вердикт | Кулдаун (× число последовательных сбоев, max ×4) |
| --- | --- | --- |
| 429 | RateLimited | 60 с |
| 401 / 403 | QuotaOrAuth | 900 с |
| 5xx | ServerError | 15 с |
| таймаут / обрыв | Transient | 5 с |
| прочие 4xx | Fatal | без кулдауна, ротация только если ключей > 1 |

Между попытками экспоненциальный backoff 1 → 2 → 4 → 8 с, максимум `min(ключи × 2, 8)` попыток.
UI показывает ротацию в реальном времени (событие `velvetdesk://agent`).

## Доктор

`🩺` в топбаре: сухой прогон (scan) и авто-исправление (fix).

- чинит битый JSON: BOM, висячие запятые, незакрытые строки и скобки, мусор после объекта (бэкап в `<file>.json.bak`);
- восстанавливает `profile.json` для осиротевшей папки;
- синхронизирует `id` / `model_id` с именем файла;
- воссоздаёт досье, если нашлась переписка без анкеты;
- уводит непривязанные вложения в `attachments/_orphans/`;
- перестраивает `global_index.json`.

## Запуск

```bash
npm install
npm run desktop:dev      # десктоп
npm run android:init     # один раз, нужен Android SDK + NDK
npm run android:dev      # телефон / эмулятор
```

Сборка релиза: `npm run desktop:build`, `npm run android:build`.

### Требования

- Node 20+, Rust 1.77+
- Linux: `libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf libxdo-dev libssl-dev`
- Android: JDK 17, Android SDK 34, NDK 27, `ANDROID_HOME` + `NDK_HOME`

### Распознавание речи

Диктовка работает тремя способами — выбор в 🔑 → «Голосовая диктовка»:

| Движок | Что нужно | Куда уходит звук |
| --- | --- | --- |
| **На устройстве** | скачать модель один раз (94–288 МБ) | никуда, всё локально |
| Gemini | ключ | в Google |
| OpenAI-совместимый | ключ (Groq, OpenAI, Together, Mistral) или локальный сервер | в выбранный сервис |

Локальные модели — 4-битный Whisper из репозиториев `onnx-community`, все мультиязычные (ru/uk/en):

| Модель | Размер | Когда брать |
| --- | --- | --- |
| tiny | ~94 МБ | короткие заметки, самая быстрая |
| base | ~139 МБ | баланс |
| small | ~288 МБ | лучшее качество для русского и украинского |

8-битные экспорты тех же моделей вдвое легче, но ни один из них не собирается
в сессию в текущей ONNX Runtime, так что берётся `q4` — проверено в браузере
на всех трёх размерах, на русской и английской речи.

Файлы скачивает Rust-ядро в `app_data/models/` и отдаёт вебвью через приватную схему `vdmodels://`,
которая пускает только внутрь этой папки (проверено тестом на traversal). Инференс идёт в вебвью
через ONNX Runtime; рантайм (12 МБ) лежит в самом приложении, так что после скачивания модели
интернет не нужен вообще.

Провайдер для диктовки может отличаться от провайдера чата: можно вести переписку через DeepSeek,
а голос распознавать локально или через Groq.

### Контекст, `/clear` и `/compact`

Индикатор рядом с кнопкой «Выполнить» показывает, сколько окна модели занимает
следующий запрос: системный промпт, досье или реестр, объявления инструментов и
переписка.

| Команда | Что делает |
| --- | --- |
| `/clear` | чат и переписка перестают уходить модели; сами сообщения, факты и досье остаются на диске |
| `/compact` | старая часть переписки заменяется конспектом, свежая остаётся дословно |
| `/help` | список команд |

При заполнении окна выше порога (по умолчанию 85%) сжатие запускается само.

### Стриминг и размышления

Ответ приходит по мере написания — и у Gemini (`streamGenerateContent?alt=sse`),
и у любого OpenAI-совместимого endpoint (`stream: true`). Если провайдер стриминг
не умеет, приложение молча повторяет запрос обычным вызовом и показывает спиннер.

Если модель думающая, её рассуждения складываются под спойлер над ответом:
у Gemini это части с флагом `thought`, у DeepSeek, Qwen и vLLM — `reasoning_content`.

### Как долго модель думает

Селектор у поля ввода: авто / без раздумий / коротко / средне / глубоко / максимум.
Выбор запоминается для провайдера. Форматы у всех разные, приложение подставляет нужный:

| Провайдер | Что уходит на провод |
| --- | --- |
| Gemini | `generationConfig.thinkingConfig.thinkingBudget` — уровень переводится в токены |
| OpenAI, Groq, Azure | `reasoning_effort` |
| OpenRouter | `reasoning: { effort }` или `{ max_tokens }` |
| Qwen / DashScope | `enable_thinking` + `thinking_budget` |

Про Gemini: в документации у моделей 3.x значится `thinkingLevel`, но живая проверка
показала, что API отвергает это поле у всех моделей, включая 3.x, — работает только
бюджет. Границы бюджета у каждой модели свои и тоже проверены запросами: `2.5-pro`
не умеет не думать и требует ≥128, `2.5-flash-lite` берёт 0 либо ≥512, а лайт-модели
3.x отвергают 0. Приложение держится внутри этих границ, а если endpoint всё же
назовёт поле неизвестным — повторяет запрос с другим написанием или без него.

### Выбор модели

Список моделей ищется по подстроке, бесплатные — сверху (у OpenRouter это суффикс
`:free` или нулевая цена в каталоге). Модели с распознаванием речи помечены.

### Настройка провайдера

Топбар → `🔑`:

1. выбери провайдера (Gemini или OpenAI-совместимый);
2. base URL, модель, версию API, температуру, доп. заголовки (для OpenRouter: `HTTP-Referer`, `X-Title`);
3. добавь один или несколько ключей — они попадут в пул ротации;
4. «Проверить связь» делает дешёвый ping-запрос.

Примеры base URL: `https://generativelanguage.googleapis.com` (Gemini),
`https://openrouter.ai/api/v1`, `https://api.deepseek.com/v1`, `http://localhost:11434/v1` (Ollama).

## Сборки в CI

`.github/workflows/build.yml` запускается **на каждый push** и собирает:

| Задание | Артефакт |
| --- | --- |
| `linux-x86_64` | `.deb`, `.AppImage`, `.rpm` |
| `windows-x86_64` | `.msi`, `.exe` (NSIS) |
| `macos-aarch64` / `macos-x86_64` | `.dmg`, `.app.tar.gz` |
| `android-apk` | `.apk` (release, подписан ключом из секретов) |

Перед сборкой прогоняются `cargo fmt`, `cargo clippy -D warnings`, `cargo test` и `tsc + vite build`.

После успешных сборок ран публикует **GitHub Release** с версией `0.2.<номер сборки>` и всеми
установщиками внутри — то есть каждый push в `master` даёт новую версию в разделе Releases.
Версия проставляется на лету (`scripts/set-version.mjs`), в репозиторий бампы не коммитятся,
поэтому цикла «релиз → новый push → релиз» не возникает.

`.github/workflows/release.yml` остаётся для ручных релизов по тегу `v*` и тоже
прикладывает подписанные APK. Ключ подписи берётся из секретов
`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`;
если их нет — APK подписывается одноразовым CI-ключом (для теста, не для стора).

Все раннеры бесплатны для публичных репозиториев.

## Обновления

Приложение само смотрит, не вышла ли версия свежее — через несколько секунд после запуска
и по кнопке «Проверить сейчас» в настройках (галка «Искать обновления при запуске» это
выключает). Если версия новее, показывается окно с заметками релиза и тремя ответами:
обновить, позже, пропустить эту версию (пропущенная больше не всплывает сама).

На десктопе обновление ставится на месте: файл скачивается, проверяется по подписи и
устанавливается, после чего приложение перезапускается. На Android установка своя —
открывается APK из релиза, дальше система спрашивает разрешение поставить его.

Манифест, который читает приложение, лежит в релизе как `latest.json`
(`scripts/update-manifest.mjs` собирает его из подписанных сборок).

**Ключ подписи.** Обновление ставится, только если сборка подписана приватным ключом
проекта. Пара ключей делается один раз:

```bash
npx tauri signer generate -w ~/.tauri/velvetdesk-updater.key
```

Публичная половина уже лежит в `src-tauri/tauri.conf.json` (`plugins.updater.pubkey`),
приватную **в репозиторий класть нельзя** — она добавляется в секреты GitHub
(Settings → Secrets and variables → Actions):

| Секрет | Значение |
| --- | --- |
| `TAURI_SIGNING_PRIVATE_KEY` | содержимое `~/.tauri/velvetdesk-updater.key` целиком |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | пароль ключа (пустая строка, если задан пустой) |

Пока секрета нет, сборка всё равно проходит: `scripts/set-version.mjs` видит отсутствие
ключа и выключает подписанные артефакты, `latest.json` выходит пустым, а приложение
откатывается к простому варианту — открывает установщик из релиза в браузере.

## Безопасность и приватность

- Ключи лежат в `secrets.json` рядом с данными (`chmod 600` на unix) и никогда не уходят никуда, кроме выбранного LLM-провайдера.
- Телеметрии нет.
- CSP запрещает всё, кроме собственных ресурсов и картинок по https.
- Тексты переписки уходят только в тот провайдер, который ты настроил.
